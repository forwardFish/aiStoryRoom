# A-Emotion M5：阶段胜利与终局摘要实现与测试证据

## 范围

M5 只增加世界无关、确定性的 `StageMilestone` 与查看者安全互动摘要：

- `CONTROL_ORIGINAL_LEDGER`
- `BREAK_OPPONENT_REPORT_CONTROL`
- `RESTORE_REFORM_MOMENTUM`
- `INACTIVE → ACHIEVED → REVOKED`
- 首次 `ACHIEVED` 产生一次 viewer-safe `STAGE_VICTORY` delivery 与一次 priority=100 modal
- 重算、刷新、worker retry 不重复 delivery/modal
- `REVOKED` 不产生胜利模态
- 互动摘要只读取当前成员拥有的安全 delivery 与其受益里程碑

不包含 M6 恢复、灰度、E2E、部署或生产数据操作。

## 权威链路

```text
已提交 ActionResolution(PASS)
  → exact action/effect/fact codes
  → 同一权威事务 evaluate StageMilestone
  → 首次 ACHIEVED 持久化 milestone 与确定性 reward
  → 写 A_EMOTION_M5_STAGE_MILESTONE_COMPILE outbox
  → worker 重新验证 run/resolution/milestone/viewer/stateVersion
  → server-side viewer-safe projection
  → StoryEvent + receiver-only EventDelivery
  → priority=100 STAGE_VICTORY modal
```

Feed 不制造状态；`reform_progress +12` 先写入 `StoryRun.stateJson.aEmotionM5`，再投影到右栏“世界局势”和批准弹窗。

## 安全不变量

- milestone 只匹配结构化 exact canonical codes，不读取自由文本，不使用中文关键词或正则。
- eventId、modalId、milestoneId、aggregateId 均为不可逆 opaque id。
- canonical event 与 viewer delivery 分离。
- delivery 不包含 raw action、raw audience、internal dedupe、sourceRoleId 或其他玩家私密 payload。
- summary 绑定当前 room/run/user/role，不允许客户端指定 viewerRoleId。
- 只有 `CONFIRMED` 项目可带 evidenceRefs。
- modal 顺序保持 `CRISIS(300) > PROMISE_BROKEN(200) > STAGE_VICTORY(100)`。

## UI 权限

- `/game` 只使用已批准的右栏“世界局势”模块。
- 阶段胜利可以使用文档批准的 modal。
- 不改顶部指标样式、不替换中央决策区、不新增主按钮或工作区。
- 390px 新布局未获单独批准，因此本阶段没有新增移动端视觉布局。
