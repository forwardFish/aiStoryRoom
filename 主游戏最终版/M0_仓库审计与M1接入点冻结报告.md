## 1. 审计结论

仓库已经具备 M1 所需的主要权威链路，不应新建第四套多人世界引擎：

```text
真实 /game
  -> continuous-story-v2-client.js
  -> ContinuousStoryV2LegacyStorage
  -> GET /api/v4/rooms/:roomId/game
  -> ContinuousStoryV2Service.game()

行动提交
  -> POST /api/v4/rooms/:roomId/game/turns/:turnId/decision
  -> ContinuousStoryV2Service.submitTurnDecision()
  -> ActionResolution / StoryRun.worldSequence / CanonFact 等权威事务
  -> publishCrossImpacts()
  -> StoryTaskOutbox(ACTOR_IMPACT_V2)
  -> executeImpactTask()
  -> NarrativeEntry(V2_CROSS_IMPACT / V2_OBSERVABLE_TRACE)

成员事件流
  -> ContinuousEventDeliveryService.publish()
  -> StoryEvent + EventDelivery + 各自 cursor
  -> GET /api/v4/rooms/:roomId/events
  -> SSE /api/v4/rooms/:roomId/events/stream
```

M1 应在 `continuous-story-v2` 权威结果提交事务中补充一个**确定性、viewer-safe 的互动投影事件**，复用 `StoryEvent/EventDelivery`，再由现有 `/game` 投影及三栏页面展示。AI 继续只负责 `NarrativeEntry` 的角色 POV，不负责 audience、来源揭露或指标变化。

## 3. 真实渲染与接口接入点

### 3.1 Web 真实入口

- `apps/web/public/game-bootstrap.js`
  - `/game?runId=...`
  - `GET /api/v4/rooms/:roomId/game`
  - `continuous_game_projection_v2` 时加载 `continuous-story-v2-client.js`。
- `apps/web/public/continuous-story-v2-client.js`
  - 创建 `ContinuousStoryV2LegacyStorage`；动态加载真实 `app.js`；当前每 1500 ms 拉取 `/game` 投影。
- `apps/web/public/continuous-story-v2-legacy-storage.js`
  - 将 `GameProjectionV2` 适配为 `app.js` 使用的既有 view。
- `apps/web/public/app.js`
  - `createStoryApp()`、`render()` 是三栏真实渲染入口。
  - `renderDecisionZone()` 是中央普通决策卡。
  - `renderManeuverPanel()` 是右栏现有四入口与 workbench。

### 3.2 API / 服务入口

- `apps/api/src/rooms.controller.ts`
  - `GET :roomId/game`
  - `POST :roomId/game/turns/:turnId/decision`
  - `GET :roomId/events`
  - `SSE :roomId/events/stream`
- `apps/api/src/rooms.service.ts`
  - `game()` 按 engineVersion 路由到 `ContinuousStoryV2Service.game()`。
  - `events()` / `eventStream()` 复用成员级增量投递。
- `apps/api/src/continuous-story-v2/continuous-story-v2.service.ts`
  - `game()` 生成 `GameProjectionV2`。
  - 权威决策事务中调用 `publishCrossImpacts()`。
  - `enqueueImpactTask()` 写 `StoryTaskOutbox(ACTOR_IMPACT_V2)`。
  - `executeImpactTask()` 发布 `NarrativeEntry(V2_CROSS_IMPACT / V2_OBSERVABLE_TRACE)`。

### 3.3 Prisma / 事务接入点

M1 不需要 schema migration，复用：

- `StoryEvent`：canonical member event、`sequence`、`dedupeKey`、`sourceActionId`；
- `EventDelivery`：per-user payload、`deliverySequence`；
- `StoryEventCursor` / `EventDeliveryCursor`：稳定序列；
- `StoryTaskOutbox`：现有 AI impact 异步叙事；
- `NarrativeEntry`：现有 POV 影响叙事；
- `StoryPlayer`：target role 到 active human user 的确定性解析。

事务边界：M1 的 viewer-safe canonical interaction event 必须在当前 action/result 事务中通过 `ContinuousEventDeliveryService.publish(tx, ...)` 写入，与权威结果同成败；AI impact 仍通过现有 Outbox 异步生成。

## 4. 文档与当前代码冲突

1. **右栏 Feed 与当前代码冲突**：现有 `/game` 只有 timeline / pendingInteractions，没有 viewer-safe Feed。不得从 `pendingInteractions` 直接复用，因为其中含 `sourceRoleId/sourceRoleName`。
2. **HIDDEN 与 AI impact 冲突**：`ACTOR_IMPACT_V2` 的服务器任务 payload 含完整 source/action，`V2_CROSS_IMPACT` 由模型生成；它可以继续作为服务端输入与目标 POV，但不能原样发到 HIDDEN Feed。
3. **顶部指标与当前代码冲突**：`gamePageProjection(...).presentation.statusMetrics` 来自静态游戏配置；当前跨玩家影响不会改变皇帝信任。M1 需要从 canonical viewer event 产生确定性绝对值覆盖，不能只改文案。
4. **事件类型映射冲突**：legacy adapter 仍判断 `entry.kind === "IMPACT"`，而 shared schema 使用 `CROSS_IMPACT/OBSERVABLE_TRACE`。M1 不能继续依赖这个错误分支。
5. **实时传输与当前客户端冲突**：仓库已有 SSE endpoint，但 V2 页面当前通过 1.5 秒全投影轮询刷新。M1 不另建实时层；保留现有轮询，避免扩大范围。
6. **草稿保护不完整**：V2 client 只额外缓存 `#customDecision`，但 `app.js` state 中还存在 maneuver draft。M1 点击 Feed / 静默刷新不得清空决策或 workbench 草稿。
7. **命名漂移**：部分 renderer 文案仍存在“人物交谈”等旧词；M1 用户可见命名必须冻结为“人物交流 / 派遣调查 / 使用筹码 / 自拟谋划”。
8. **正式承诺不属于 M1**：仓库已有通用 `CommitmentV2` 创建逻辑，但 M4 才实现 `SimplePromise` 与 deterministic broken/reveal；M1 不吸收或重写该链路。

## 6. M1 风险与控制

| 风险 | 控制 |
|---|---|
| 词法规则误触发 | 仅 `sangtian + multiplayer + xunfu -> zhejiang_governor + PRIVATE/LIMITED + 原册/粮册 + 副本/隐藏/暂缓`；flag 默认关 |
| HIDDEN 泄源 | 独立 safe schema；运行时 forbidden-key 深度检查；API contract adversarial test；事件 ID 使用不可逆摘要，不暴露 action/role 标识 |
| 重复事件 / 重复指标 | StoryEvent `dedupeKey` + EventDelivery cursor；指标使用绝对 from/to，不累加重复请求 |
| 无关角色收到事件 | 只解析目标 role 的 active human StoryPlayer；无用户则不投递 |
| 页面刷新丢草稿 | 不自动打开中央卡；点击才打开；保留 `state.customText` 与 `state.maneuverDraft` |
| 与现有 AI impact 重复展示或泄源 | 精确 M1 HIDDEN human 切片不再为同一目标入队 legacy AI impact task；AI-only 目标和其他现有 impact 路径保持不变 |
| 旧房间 / Solo 回归 | feature flag 默认 false；编译器同时要求 multiplayer + Sangtian；无 feed 时输出完全兼容 |
| M2 范围侵入 | M1 只提供 sequence/cursor/aggregateKey 基础；不实现 durable seen/ack/disclosure upgrade |

## 7. M1 停止条件

M1 完成以下单条垂直链路后停止，不进入 M2：

```text
巡抚隐藏/只交副本
  -> 总督 viewer-safe RELATED Feed
  -> 皇帝信任 43 -> 37（同一权威投影）
  -> 点击打开 CROSS_IMPACT
  -> 派遣调查 / 公开质问只预填现有 workbench
  -> 暂不回应不消耗谋划
  -> HIDDEN 无来源、无 raw payload，事件 ID 无原始 action/role 标识
  -> 无关角色无 delivery
  -> 重复编译/读取幂等
```
