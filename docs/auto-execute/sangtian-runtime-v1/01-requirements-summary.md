# 需求摘要

## P0

- `R-D2-01`：外部自由输入只能生成闭合的结构化意图；内部 effect 由服务端编译并校验权限、知识、对象、资源、时限和版本。
- `R-D2-02`：六席密封提交、默认政策、稳定冲突排序、custody/version、事件账本、Frozen 与恢复必须确定且幂等。
- `R-D3-01`：每次有效行动形成 `PLAYER_ACTION / VISIBLE_REACTION / CONSEQUENCE_OR_NEW_INFO / NEXT_PRESSURE` 四个可追溯节拍。
- `R-D3-02`：AI/Narrator 只能解释权威结果，不能补造事实、改变胜负或泄漏席位私密知识；缺节拍时使用 authored fallback。
- `R-D3-03`：五个 AI 席位、NPC 先手/反应、N2/N4/N7 条件应变与 Finale 使用同一事件和投影边界。
- `R-D4-01`：沿用 `/game` 三栏；显示身份/私人开场、2—3 条安全建议、自由输入、提交确认和结构化可见后果。
- `R-D4-02`：“我先睡一下”必须真实解析为 REST/DELAY，时间推进半日，五席/NPC 先手，压力 +1，玩家被急报唤醒并进入新现场。
- `R-INT-01`：最终以 1 人 + 5 AI 从 P0 到 N7/Finale 的真实链路、恢复和浏览器证据验收。

## MVP 边界

只做能证明纵向闭环的最小 UI 与运行链；高级记忆视图、复杂 overlay、卡牌 DSL、排行榜、终局自由演说和视觉重构均不在范围。
